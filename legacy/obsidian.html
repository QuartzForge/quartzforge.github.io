obsidian
Data mapper tipado
estável · v0.9

A query devolve um tipo que só conhece o que você carregou.

Não é um aviso, nem um linter, nem um modo estrito opcional. O retorno de .preload(:customer) é literalmente um tipo diferente do retorno de .preload(:customer, :line_items) — e o compilador trata a diferença. 

# shard.yml
dependencies:
  obsidian:
    github: quartzforge/obsidian
    version: ~> 0.9
Modelo e migração Ver o ecossistema

Crystal ≥ 1.14·PostgreSQL 14+·MIT

src/models/invoice.cr 
class Invoice < Obsidian::Model
  table :invoices

  column id          : UUID = UUID.v7, primary: true
  column total_cents : Int64
  column status      : Status
  column metadata    : JSON::Any, type: :jsonb
  column tags        : Array(String), default: %w[]
  column issued_at   : Time
  column deleted_at  : Time?     # soft delete opt-in

  belongs_to customer   : Customer
  has_many   line_items : LineItem
  has_many   payments   : Payment

  scope :overdue { where("issued_at < ?", 30.days.ago) }

  enum Status
    Draft; Sent; Paid; Overdue
  end
end
# the builder is composable: each step returns another query
base = Invoice.query.overdue.where(status: :sent)

if customer_filter
  base = base.where(customer_id: customer_filter)
end

report = base
  .preload(:customer, line_items: :product)
  .order(issued_at: :asc)
  .limit(500)

# two queries in total, not 501
report.each do |invoice|
  puts "#{invoice.customer.name}: #{invoice.line_items.sum(&.amount_cents)}"
end

# aggregates without loading a single row
Invoice.query.where(status: :paid).sum(:total_cents)
Invoice.query.group_by(:status).count
Obsidian.transaction do |tx|
  invoice = Invoice.create!(
    customer_id: attrs.customer_id,
    total_cents: attrs.total_cents,
    issued_at:   Time.utc,
  )

  attrs.line_items.each { |i| LineItem.create!(invoice_id: invoice.id, **i.to_named) }

  # the job joins the SAME transaction (pulse integration)
  SendInvoice.new(invoice.id).enqueue(tx)

  # a rollback here undoes invoice, line items and job together
  raise Obsidian::Rollback.new unless Credit.reserve(invoice, tx)
end

Como isso funciona

Um tipo por combinação de preload.

A macro de query gera, na compilação, um tipo cujos métodos de relação existem apenas para as relações pedidas. Não há verificação em runtime porque não há o que verificar: o método simplesmente não foi gerado.

o que o compilador enxerga
Invoice.query.preload(:customer)
#  => Obsidian::Loaded(Invoice, {customer: Customer})
#     .customer     ✓ exists
#     .line_items   ✗ does not exist

Invoice.query.preload(:customer, line_items: :product)
#  => Obsidian::Loaded(Invoice, {
#       customer:   Customer,
#       line_items: Loaded(LineItem, {product: Product})
#     })
#     .customer                   ✓
#     .line_items                 ✓
#     .line_items.first.product   ✓
#     .payments                   ✗
  • Aninhamento também é verificadoline_items: :product só libera .product dentro de .line_items. Um nível esquecido continua sendo erro de build.
  • Passa por assinatura de métodoUma função que recebe Loaded(Invoice, {customer: Customer}) documenta no tipo o que ela precisa que já esteja carregado.
  • O autocompletar segue a mesma regraRelações não carregadas não aparecem na lista do editor — você descobre o problema enquanto digita.
  • Escapatória explícita quando precisainvoice.load(:payments) existe e dispara uma query — mas você teve que escrever, então está visível na revisão.

Mapeamento de tipos

Postgres de verdade, não o menor denominador comum.

Mapeamento entre tipos Crystal e Postgres
CrystalPostgresObservação
UUIDuuidUUID.v7 como padrão dá ordenação temporal no índice primário.
TimetimestamptzSempre UTC na aplicação; a conversão de fuso fica na borda.
Enumenum nativoA migração cria o tipo; adicionar valor é migração, não deploy silencioso.
JSON::AnyjsonbOperadores ->> e @> disponíveis no builder.
Array(T)T[]Array nativo, com ANY e && no where.
BigDecimalnumericSem ida e volta por float — valores monetários chegam exatos.
T?NULL permitidoNulidade é do tipo Crystal; a migração é gerada a partir dele.
Quando não usar obsidian

Ele assume PostgreSQL e não pretende ser portátil para MySQL ou SQLite — os tipos nativos e o SKIP LOCKED que o pulse aproveita fazem parte do desenho. Se você precisa de vários bancos, um driver genérico serve melhor.
