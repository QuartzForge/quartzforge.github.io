vault
Cliente OAuth
estável · v0.9

Cada provedor devolve o que quer. vault devolve sempre a mesma coisa.

O Google manda sub, o GitHub manda id numérico e o e-mail em outra chamada, o Microsoft manda oid. Você recebe uma Vault::Identity — e escreve o fluxo de login uma vez só. 

# shard.yml
dependencies:
  vault:
    github: quartzforge/vault
    version: ~> 0.9

Crystal ≥ 1.14·OAuth 2.1 + PKCE·MIT

src/oauth.cr 
require "vault"

Vault.configure do |v|
  v.provider :google,
    id:     ENV["GOOGLE_ID"],
    secret: ENV["GOOGLE_SECRET"],
    scopes: %w[openid email profile]

  v.provider :github,
    id:     ENV["GITHUB_ID"],
    secret: ENV["GITHUB_SECRET"],
    scopes: %w[read:user user:email]

  v.redirect_uri "https://app.example.com/oauth/:provider/callback"

  # PKCE is the default; turning it off must be spelled out
  v.pkce true
  v.timeout 8.seconds
end
get "/login/:provider" do |c|
  challenge = Vault.start(c.param("provider"))
  c.session["oauth"] = challenge.to_cookie   # state + code_verifier
  c.redirect challenge.url
end

get "/oauth/:provider/callback" do |c|
  case r = Vault.exchange(
             c.param("provider"),
             code:      c.param("code"),
             challenge: c.session["oauth"])
  when Vault::Success
    # r.identity: id, email, email_verified, name, avatar_url
    user = User.from_identity(r.identity)
    Session.open(c, user)
    c.redirect "/dashboard"
  when Vault::Failure
    # :invalid_state | :expired_code | :scope_denied | :network
    c.problem(401, r.reason)
  end
end
# any OAuth 2 provider fits in a single class

class GovBr < Vault::Provider
  name :gov_br

  authorize_url "https://sso.acesso.gov.br/authorize"
  token_url     "https://sso.acesso.gov.br/token"
  profile_url   "https://sso.acesso.gov.br/userinfo"

  # the only required method: normalize the profile
  def identity(profile : JSON::Any) : Vault::Identity
    Vault::Identity.new(
      id:             profile["sub"].as_s,
      email:          profile["email"]?.try(&.as_s),
      email_verified: profile["email_verified"]?.try(&.as_bool) || false,
      name:           profile["name"]?.try(&.as_s),
      avatar_url:     nil,
    )
  end
end

Provedores incluídos

Cinco prontos, e um contrato para o sexto.

O que muda entre provedores é a URL, o escopo e o formato do perfil. O vault guarda essas três coisas e expõe o resto igual.

PKCE ligado por padrão

Desligar é possível, mas exige escrever v.pkce false — a escolha insegura tem nome.

State verificado sempre

O state é gerado, guardado e conferido pelo próprio vault. Não há caminho em que ele seja ignorado.

Erros nomeados

Vault::Failure traz um símbolo, não uma string de mensagem — dá para tratar cada caso sem comparar texto.

Fronteira do escopo

É um cliente OAuth. Não é um sistema de contas.

  • FazMonta a URL de autorização, troca o código por token, renova, revoga e normaliza o perfil.
  • Não fazNão cria usuário, não gerencia sessão, não define papéis nem permissões. Isso é do seu domínio.
  • Por quêVincular identidade externa a conta interna é uma regra de negócio — quem decide se dois e-mails iguais são a mesma pessoa é você.
Quando não usar vault

Se você precisa ser um provedor OAuth — emitir tokens para aplicações de terceiros — vault não serve: ele é só o lado cliente. Um servidor de autorização é outro problema, com outro conjunto de riscos.
