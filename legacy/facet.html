facet
Validação isolada
estável · v0.9

Validação que não sabe o que é HTTP.

facet não conhece requisição, banco nem framework. Ele recebe um valor bruto e devolve ou um struct tipado, ou a lista de erros — exatamente igual dentro de uma API, de um consumidor de fila ou de um CLI. 

# shard.yml — pulls in nothing else
dependencies:
  facet:
    github: quartzforge/facet
    version: ~> 0.9

Crystal ≥ 1.12·zero dependências·MIT

src/schemas/signup.cr 
require "facet"

struct Signup
  include Facet::Schema

  field name      : String, size: 2..120, strip: true
  field email     : String, format: :email, downcase: true
  field password  : String, size: 12..128
  field cpf       : String, format: :cpf
  field birthdate : Date, lte: -> { Date.today - 18.years }
  field terms     : Bool, accepted: true
  field address   : Address?   # nested schema

  validate :password_differs_from_email do |f|
    f.error(:password, :weak_password) if f.password.includes?(f.email.split("@").first)
  end
end
# same schema, with no server in between:
# importing a CSV from the terminal

CSV.each_row(File.read("customers.csv")) do |row, i|
  case r = Signup.validate(row.to_h)
  when Facet::Valid
    Customers.create!(r.value)
  when Facet::Invalid
    STDERR.puts "row #{i + 1}: #{r.errors.map(&.field).join(", ")}"
  end
end

# and inside a queue job, the same:
def perform
  r = Signup.validate(@payload)
  raise Pulse::Discard.new(r.errors) if r.invalid?
  Customers.create!(r.value)
end
# every error carries a stable key; the text is yours

Facet.messages "pt-BR", {
  size:          "deve ter entre %{min} e %{max} caracteres",
  format_email:  "informe um e-mail válido",
  format_cpf:    "CPF inválido",
  accepted:      "é preciso aceitar para continuar",
  weak_password: "a senha não pode conter seu e-mail",
}

# serialization comes out ready for the response
r.errors.to_json(locale: "pt-BR")
# => [{"field":"password","rule":"weak_password","detail":"…"}]

Decisões de projeto

Quatro escolhas que mantêm o pacote pequeno.

Resultado, não exceção

validate devolve Facet::Valid ou Facet::Invalid. O case exaustivo do Crystal obriga o tratamento — não existe caminho onde o erro passa despercebido.

Coerção declarada

strip, downcase e conversão de tipo acontecem porque você escreveu, não porque a biblioteca adivinhou o que você queria.

Chave estável por erro

Cada falha carrega uma chave (:size, :format_cpf). O texto vive na sua tabela de mensagens e pode mudar sem quebrar o cliente da API.

Sem acoplamento reverso

quartz e obsidian sabem usar facet. facet não sabe que eles existem — e é por isso que ele roda em qualquer projeto Crystal.

Regras embutidas

As comuns já vêm; o resto é um bloco.

Regras de validação disponíveis
OpçãoAplica aEfeito
size:String, Array, HashFaixa de tamanho, aberta dos dois lados (..280, 1..).
format:String:email, :url, :uuid, :cpf, :cnpj ou um Regex.
in:qualquerRestringe a um conjunto de valores aceitos.
gte: / lte:Number, Time, DateLimite inclusivo; aceita Proc para valores calculados.
accepted:BoolExige true — termos de uso, consentimento.
strip: / downcase:StringNormaliza antes de validar.
validate :name do … endo schema inteiroRegra própria com acesso a todos os campos já convertidos.
Quando não usar facet

Se o seu framework já traz validação integrada ao ciclo de vida do modelo e você está satisfeito com ela, trocar só para desacoplar não paga o custo. facet brilha quando a mesma regra precisa valer em mais de um ponto de entrada.
