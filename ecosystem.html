Ecossistema

Cinco projetos com escopos que não se sobrepõem.

Cada um resolve um problema inteiro e para por aí. Você escolhe quantos entram no seu shard.yml — e nenhum deles reclama da ausência dos outros.

5 projetos
quartz
Framework HTTP
estável

APIs robustas em Crystal: roteador em radix tree resolvido na compilação, controllers com parâmetros tipados, middlewares declarados na ordem em que rodam e respostas de erro em RFC 9457.

  • Rotas nomeadas com geração reversa de URL
  • Streaming, SSE e WebSocket na mesma app
  • Contexto de requisição com RequestID propagado
v0.9·MIT abrir →
obsidian
Data mapper tipado
estável

Mapeia tabelas para tipos Crystal e verifica o carregamento de relações em tempo de compilação. Uma relação fora do preload não existe no tipo devolvido — logo, não compila.

  • Query builder componível, sem string solta
  • Migrações versionadas com forge db
  • Enums, jsonb e arrays mapeados nativamente
v0.9·MIT abrir →
pulse
Fila de jobs
beta

Fila de background nativa de Postgres. O job entra na mesma transação que gravou o dado, então não existe o caso clássico de “enfileirou mas o commit falhou”.

  • Retentativas com backoff e fila morta
  • Unicidade por chave e janela de tempo
  • Agendamento cron dentro do próprio binário
v0.8·MIT abrir →
facet
Validação isolada
estável

Validação de verdade desacoplada: não conhece HTTP, não conhece banco, não conhece o QuartzForge. Roda igual dentro de um consumidor de fila, de um CLI ou de outro framework.

  • Coerção declarada por tipo, sem adivinhação
  • Schemas aninhados e listas com limite
  • Mensagens traduzíveis, com chave estável por erro
v0.9·MIT abrir →
vault
Cliente OAuth
estável

Um cliente OAuth 2.1 para vários provedores com a mesma saída. Cada provedor devolve o perfil no formato dele; vault devolve sempre uma Identity.

  • PKCE e verificação de state por padrão
  • Renovação de token e revogação explícitas
  • Provedor customizado em uma classe
v0.9·MIT abrir →

Matriz de compatibilidade

O que cada projeto exige — e o que ele só aproveita se estiver lá.

“Opcional” significa que o projeto detecta o outro em tempo de compilação e liga a integração. Sem ele, nada quebra: você só escreve a cola à mão.

Dependências e integrações entre os projetos do QuartzForge
Projeto Crystal Exige Integra se presente Estado
quartz ≥ 1.14 nada além da stdlib facet · vault · obsidian estável
obsidian ≥ 1.14 PostgreSQL 14+ facet · pulse estável
pulse ≥ 1.14 PostgreSQL 14+ obsidian (mesma conexão) beta
facet ≥ 1.12 nada além da stdlib quartz · obsidian estável
vault ≥ 1.14 cliente HTTP da stdlib quartz (rotas de callback) estável
Uma infra só

Fora do Postgres, o conjunto inteiro não pede nenhum serviço externo obrigatório.

Adoção parcial é caso de uso, não gambiarra

facet e vault são os mais usados fora do QuartzForge — e é assim que devem ser.

pulse ainda é beta

A API de agendamento pode mudar antes do 1.0. As mudanças ficam registradas no changelog do projeto.

Projeto novo

API que já existe
